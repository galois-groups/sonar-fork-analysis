# Troubleshooting

Look up a message the action printed to see what it means and what to do.
Messages are grouped by the workflow that prints them. Warnings and notices show
up as annotations on the run. Errors fail the step. The line for each setting,
path, file or link left out is in the log only. One warning counts them.

## Inputs

| Message                                    | What it means                                                                    |
| ------------------------------------------ | -------------------------------------------------------------------------------- |
| Input required: project-key                | Set `project-key` in both workflows.                                             |
| Invalid project key '…'                    | Project keys can only contain letters, digits, `.`, `_`, `:` and `-`.            |
| Unknown mode '…'<br>Unknown build tool '…' | There's a typo in `mode` or `build-tool`. See [inputs](configuration.md#inputs). |

| Could not note the direct analysis for the fork path: …                                                                                                                                                                         | The marker couldn't be uploaded, so the Sonar workflow will report that the build left nothing to analyse. ## Sonar workflow

| Message                                                                                                                                                                                                                                                                        | What it means                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No … artifact: the build left nothing to analyse.                                                                                                                                                                                                                              | The build didn't run the action for this project key. Check that both workflows use the same `project-key` and that the Sonar workflow only runs after builds that ran the action. See [builds that don't always run the action](configuration.md#builds-that-dont-always-run-the-action). The build's artifact also expires after a day. Until then you can rerun the Sonar workflow. Later, rerun the build, which starts the Sonar workflow again. |
| No open pull request has … as its head any more; a newer run analyses it.                                                                                                                                                                                                      | The pull request got new commits or was closed before the analysis started. Nothing to do.                                                                                                                                                                                                                                                                                                                                                            |
| The run names no branch to find its pull request by.                                                                                                                                                                                                                           | GitHub gave the run no branch, so the action can't tell which pull request it belongs to and analyses nothing.                                                                                                                                                                                                                                                                                                                                        |
| The run comes from a branch of … rather than a pull request: nothing to analyse.                                                                                                                                                                                               | A run from a fork's branch that wasn't triggered by a pull request started the Sonar workflow. That can happen when a pull request adds its own workflow with the same name as your build. The action ignores it, so there's nothing to do.                                                                                                                                                                                                           |
| … open pull requests have this head, analysing #…                                                                                                                                                                                                                              | Several pull requests share the analysed commit. The build didn't say which one it ran for. The action analyses the first one.                                                                                                                                                                                                                                                                                                                        |
| The build's pull request #… is closed or has newer commits: nothing to analyse.                                                                                                                                                                                                | Another pull request shares the analysed commit. Its own run analyses it. The one the build ran for was closed or got new commits before the analysis started. The status says the analysis was skipped.                                                                                                                                                                                                                                              |
| No Sonar token available, set the sonar-token input.                                                                                                                                                                                                                           | Pass `sonar-token` to the action in the Sonar workflow.                                                                                                                                                                                                                                                                                                                                                                                               |
| … was prepared by an incompatible version of this action                                                                                                                                                                                                                       | Use the same version of the action in both workflows.                                                                                                                                                                                                                                                                                                                                                                                                 |
| The workspace holds files but no checkout: …                                                                                                                                                                                                                                   | A step before the action left files in the workspace, but no checkout. The action only checks out into an empty workspace. Remove that step or replace it with [your own checkout](configuration.md#your-own-checkout) of the analysed commit. On a self-hosted runner, another job may have left the files. See [self-hosted runners](configuration.md#self-hosted-runners).                                                                         |
| The checkout is at … but the analysis is for …<br>The checkout is shallow …<br>The checkout stored credentials in .git/config …<br>The checkout's origin holds credentials …<br>The checkout's origin is not …<br>The checkout holds files that aren't the analysed commit's … | A step before the action checked out the code. That checkout doesn't meet the [requirements](configuration.md#your-own-checkout). Another job on a self-hosted runner may also have left its checkout in the workspace. See [self-hosted runners](configuration.md#self-hosted-runners).                                                                                                                                                              |
| Could not tell whether the workspace holds a checkout: …                                                                                                                                                                                                                       | git couldn't read the workspace and says why. On a self-hosted runner, it's often _dubious ownership_: an earlier job, for example one in a container, left files owned by another user. Empty the workspace, see [self-hosted runners](configuration.md#self-hosted-runners).                                                                                                                                                                        |
| git … failed with exit code …                                                                                                                                                                                                                                                  | The action couldn't check out the pull request. Git's own message follows.                                                                                                                                                                                                                                                                                                                                                                            |
| Could not look up the pull request: GitHub answered …                                                                                                                                                                                                                          | Give the Sonar job `pull-requests: read`.                                                                                                                                                                                                                                                                                                                                                                                                             |
| The artifact contains a link or special file: …<br>… holds settings that are not all text                                                                                                                                                                                      | Someone tampered with the artifact, so the action analyses nothing.                                                                                                                                                                                                                                                                                                                                                                                   |
| The artifact gives … no base directory in the checkout<br>Invalid module id …                                                                                                                                                                                                  | The artifact names modules or directories the checkout doesn't have. A real build does this when the base branch gained a module after the pull request branched off. [Update the pull request or build its head](configuration.md#which-commit-the-build-tests). Otherwise, someone may have tampered with the artifact. If you think it's a bug, please open an issue.                                                                              |
| The analysis left out …. The job summary lists them and the log says why.                                                                                                                                                                                                      | One warning for everything the analysis left out. The log has a line for each with the reason. The rows below explain these lines.                                                                                                                                                                                                                                                                                                                    |
| Dropped settings a build never ships: …                                                                                                                                                                                                                                        | Either someone tampered with the artifact or the two workflows run different versions of the action.                                                                                                                                                                                                                                                                                                                                                  |
| Dropped …: it holds a placeholder the scanner would expand<br>Dropped …: it holds half of a character<br>Dropped …: the scanner reads it as one path<br>Dropped … entry: …                                                                                                     | The action couldn't check this setting or one of its paths safely. | Removed …: a link leading out of the checkout                                                                                                                                                                                                                                  | A link in the pull request leads outside the checkout or nowhere. The analysis goes on without it.                                                                                                                                                                                                                                                                                                                                                    |
| Skipped …: …                                                                                                                                                                                                                                                                   | A file from the artifact wasn't unpacked. | Skipped link …: …<br>Skipped a link: … names no path and target                                                                                                                                                                                                                | A link the artifact asks for in `node_modules` doesn't stay in the checkout, isn't in a `node_modules` directory or doesn't lead to a directory. | build-arguments set …: that language's analyzer runs with the token.                                                                                                                                                                                                           | You set this language's file patterns in `build-arguments`, so its analyzer runs. ## Commit status

| Message                                         | What it means                                                                                                                |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Analysing<br>Analysed                           | The analysis is running or has finished. The status links to the run.                                                        |
| The build left nothing to analyse               | See _No … artifact_ under [Sonar workflow](#sonar-workflow).                                                                 |
| Skipped: the build was for #…                   | See _The build's pull request #… is closed_ under [Sonar workflow](#sonar-workflow).                                         |
| The analysis failed, see the run                | Something else went wrong. The run's log says what.                                                                          |
| The analysis ended without reporting its result | The Sonar job stopped before the action finished, for example because it was cancelled or timed out. The run's log says why. |
